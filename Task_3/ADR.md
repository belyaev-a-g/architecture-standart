Менеджер связывается с клиентом и предлагает условия депозита<br>4. Если клиент согласен, менеджер направляет его в отделение для идентификации.|

Бэкенд интернет-банка иницирует отправку СМС с кодом подтверждения через шлюз телеком-оператора<br> 5. Клиент вводит код подтверждения<br> 6. Бэкенд интернет-банка сохраняет заявку и передает ее в АБС<br> 7. Бэкенд интернет-банка иницирует отправку СМС с уведомлением о принятии заявки через шлюз телеком-оператора<br> 8. АБС иницирует отправку СМС-уведомления об открытии депозита (через смс-шлюз телеком оператора)<br> 6. Клиент получает СМС-уведомление об открытии депозита.|





### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**
Опишите здесь нефункциональные требования и архитектурно значимые требования.


|**№**|**Требование**|
|-------|------------------------------------|
| **U** | **Удобство использования (Usability)** |
| U1     | Интерфейс работы будет максимально удобным для клиента |
| U2    | Пользователи при работе должны видеть привычные цвета и брендированные элементы|
| **R** | **Надёжность (Reliability)**           |
| R1    | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев                                |
| R2    | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку                                |
| **P** | **Производительность (Performance)**   |
| P1    | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды                                |
| P2    | Предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД                                |
| **S** | **Поддерживаемость (Supportability)**  |
| S1    | При доработках во всех системах нужно как можно больше использовать технологии, которые уже есть в банке. Например, базы данных MS SQL и Oracle.                                |
| S2    | Предусмотреть разработку документации для дальнейшего расширения системы                                |
| **+R**| **+ Ограничения (Restrictions)**       |
| +R1   | Данные на сайте необходимо защищать с помощью механизма шифрования трафика                                |
| +R2   | Реализовать СМС подтверждение открытия депозита через интернет-банк силами команды разработки банка                                |
| +R3   | Данные в интернет-банке необходимо защищать с помощью механизма шифрования                                 |
| +R4   | Подумать о переводе интернет-банка на микросервисную архитектуру, но пока только в рамках задачи открытия депозитов.                                 |
| +R5   | Если нужны очереди сообщений, то лучше использовать Kafka на перспективу                                |
| +R6   | текущая версия платформы интернет-банка несовместима с Kafka                                |
